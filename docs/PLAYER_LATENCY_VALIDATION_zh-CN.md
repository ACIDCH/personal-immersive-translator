# 视频播放器兼容性与实时字幕验收规则

状态：2026-10-16，实验开发分支。以下自动化测试不代表线上平台生产兼容性已经通过。

## 播放器识别优先级

1. 使用当前网页可访问的原生 HTML5 TextTrack 字幕轨及视频时间戳；
2. 用户已经打开原字幕时，尝试识别可见的 YouTube、Netflix、Panopto 字幕 DOM，不读取隐藏文本、不跨越 iframe 同源限制；
3. 用户自行导入获得授权的 SRT/VTT，并按当前可读视频的时间轴同步；
4. 字幕源不存在时，在用户明确同意下使用本机 whisper.cpp 分段 ASR，再通过标准翻译服务翻译文本。

**不能绕过登录、DRM、字幕版权保护、网页隔离。** Panopto 的字幕下载按钮受管理员全站设置影响，默认并非开启；即便用户有课程播放权限也不意味着下载权限已开放。参考：https://community.panopto.com/discussion/2331/quarterly-release-2024-04-04-feat-transcript-download

## 测试维度

| 场景 | 已自动验证 | 正式发布门槛 |
| --- | --- | --- |
| YouTube 风格可见字幕 | 真实 Chrome DOM 模拟 | 用户授权的线上影片，字幕轨切换、倍速及 30 分钟持续播放 |
| Netflix 风格嵌套字幕 | 真实 Chrome DOM 模拟，隐藏子节点不会残留 | 已授权账户与不同 UI/DRM 环境 |
| Panopto 课堂字幕 | 真实 Chrome DOM 模拟，播放器没有暴露 video 仍可识别字幕 | 机构许可下的真实课程、内嵌 iframe 的权限和变化 |
| 跨域 iframe | 实际 Chrome 测试明确提示来源受限 | 只能在源站授权或者独立专用权限适配后访问 |
| SRT/VTT 字幕 | 实际 Chrome 5000 条深度跳转测试 | 30 分钟 1x/2x 播放与滑动、时间轴偏差检测 |
| 无字幕视频 ASR | 16 kHz 重采样、有限缓存、语音片段管理、过期丢弃 | 真正加载 whisper.cpp 多语言模型，连续播放并统计延迟、错误率 |
| 单位语音翻译 | 单请求在途，最新片段取代队列里的旧片段 | 网络抖动、429、30 分钟压力、设备性能与流停止验收 |

## 延迟指标（目标，**不是已达成的实测值**）

- 原始文字字幕已提供时，翻译显示中位延迟目标 ≤ 1.5 秒，p95 目标 ≤ 3 秒；依赖所选翻译服务、网络及文本长度。
- 本机语音 ASR：以约 3 秒输入片段为基础，端到端估计 p95 目标 ≤ 8 秒，实际测量须包括语音片段收集、ASR 和翻译 API。超过 12 秒的结果不应作为当前字幕闪现，应丢弃并提示降低模型规模。
- 音频保留队列最多约 6 秒，实时识别请求一次最多一个在途；服务变慢时放弃过时音频，不允许无限积压。
- 暂停、停止、页面跳转或关闭后不得恢复旧字幕，也不得自动继续上传音频。
- 30 分钟连续播放中必须记录字幕成功率、丢弃量、错误量、p50/p95 延迟和 CPU/内存使用情况。静态测试只能验证架构，没有用户真实电脑实测就不能宣布性能达标。

## 现有证据

- tests/player_compat_e2e.py：三个服务的模拟 DOM 显示、变化、隐藏、停止和跨域提示；在真实 Chrome 上运行，但不是线上网站。
- tests/live_caption_e2e.py：连续多个模拟 ASR 文本进入页面，测试最新字幕优先、请求合并、显示延迟统计和停止清理。
- tests/live_soak.test.js：模拟 30 分钟持续产生 PCM 音频及九秒慢速 ASR，验证缓存被严格限制；**不涉及真实语音模型或真实性能指标**。
- tests/extension_smoke.py：真实 Chrome Manifest V3 后台、弹窗、设置和工具页加载；不代表真实账户的视频字幕抓取已成功。

最终结果应对比现有沉浸式翻译插件，按照相同语种、硬件和翻译服务进行盲评及延迟对照，未经数据验证不得宣称优于现有插件。
