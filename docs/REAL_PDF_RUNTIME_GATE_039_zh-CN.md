# v0.3.9 PDF 扫描检测、BabelDOC 子进程与真实验收入口

日期：2026-10-16。当前属于开发分支，不合并主分支，不修改正式 UI，也不生成或交付中间安装包。

## 实施变化

1. **修正扫描件检测**：之前把“页面文字少于 30 字符”直接解释为扫描件，导致空白页、简短标题页和只有小图标的封面误触发 OCR。现在遍历 PDF 全部页面：先检查是否存在可搜索文字，再用 PDF 图像的实际渲染区域识别超过页面约 7% 的栅格图像，避免空白页误报，同时仍检查论文后半部分的扫描附录。加密文件明确拒绝。
2. **真正的 OCRmyPDF → 独立 CLI 子进程联通测试**：CI 先以图片生成栅格扫描 PDF，调用真实 OCRmyPDF/Tesseract/Ghostscript 得到可检索 PDF，再交给单独启动的 CLI 合同替身生成真实可读取的双语形式测试输出；验证本机 HTTP 请求、临时 TOML 0600 私有权限、子进程参数、输出 PDF 结构以及失败时无密钥/原文泄露。
3. **真实 BabelDOC 执行入口**：新增 `python -m benchmarks.babeldoc_real_acceptance`，必须由操作者同时提供合法 PDF 路径、本机已安装且兼容的 BabelDOC、自己的翻译 API Key，以及 `--acknowledge-billed-translation` 明确承认可能发生模型资源下载与远程翻译费用。输出路径必须不存在，拒绝覆盖已有文件。完成后运行 PDF 缺页、文字不可提取、越界文本统计，仅返回匿名结构指标，并要求对复杂排版人工视觉核验。

## 测试层级说明

| 证据 | 当前情况 | 不能推断 |
| --- | --- | --- |
| 实际 OCRmyPDF 扫描 PDF | 真实外部 OCR 引擎执行，输出可复制文字，并在后续验证环节读取 | 不保证真实双栏或手写文字识别率 |
| BabelDOC 兼容 CLI 子进程 | 真正执行独立子进程、读取临时 TOML、生成真实 PDF，模拟成功和失败 | 测试执行的是本项目专用合同替身，**不是官方 BabelDOC 翻译引擎** |
| BabelDOC `--help` | 检查用户本机实际已安装命令的支持参数 | 不保证模型资源完整、网络/API 可用、版面还原正确 |
| 有付费风险的真实翻译入口 | 代码已提供；用户未明确运行时不发起付费翻译 | 目前**没有**带用户私钥和真实 BabelDOC 的端到端翻译验收 |
| 译后 PDF 结构质量 | 实际 PyMuPDF 检查页数、文字提取和越界文字对象 | 无法完全量化公式、图片、语义、行距和双栏保真度 |
