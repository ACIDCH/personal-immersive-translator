# PIT V2｜真实 Windows / Chrome 验收入口（Draft，不是发布证书）

本清单用于安装 **PR #55 最新 WXT 工件**后逐项检查真正的生产调用链。不要将 CI 的受控网页/模拟 HTTP 接口当成真实账户或在线播放器已成功；不提交私人网页、API Key、邮件、Cloud Token、PDF 原稿。

## 0. 安装确认与版本隔离

1. 从 PR #55 最新绿色 **Multimodal Platform UI & BYOK validation** Actions 的 `multimodal-wxt-web-integration-test` 下载 ZIP。解压到固定目录；在 `chrome://extensions` 选择包含 `manifest.json` 的文件夹。关闭旧 PIT 和其他会同时注入译文的插件，避免双重翻译。
2. 打开 Popup、设置中心和文件工作台，确认三者属于同一个扩展 ID；记录 Chrome 版本、Windows 版本、扩展 ID、Commit 和验证日期。安装包可能与 Codex 的本机 Downloads 副本不同，以 Actions HEAD 工件为准。
3. 已有账户配置需要备份：在设置页面导出加密保险库（如已启用），不要在聊天中共享 Key；升级到新 build 前保存配置。

## 2. 需要本人授权或服务部署的条件验收

- **SYNC-01 Google 登录**：先在仅 PIT 的 Supabase 项目中启用 Google OAuth，设好 Client ID/Secret 和扩展回调 Redirect URLs，然后用本人账号手动登录。两台真实浏览器/设备使用相同账号、密钥保险库密码，测试「登录→加密上传→新设备解锁→冲突处理→退出保留本地」。**不要将 OAuth Secret 或保险库密码发送给任何聊天助手。**
- **ASR-01 Whisper**：用户单独部署/启用允许使用的本地或云端 ASR 后，选择本人有权捕获的非 DRM 音频，检查 16kHz PCM16 通路、语言、延迟、停止后无字幕残留；未启用时不应该假显示识别成功。
- **PDF-02 BabelDOC**：独立 FastAPI+BabelDOC 容器报告 health ready 后再上传复杂扫描或双栏文档；检查原始页数、字形位置、图表公式、下载和存储过期。配置真正持久卷才能验收「完成结果跨容器重启下载」；运行中任务重启仍应失败而非假成功。
- **VID-02 公开视频/登录网站**：仅在有权访问的真实 YouTube、Panopto、Netflix、Bilibili 播放器中执行 CC、seek、倍速、全屏、视频切换对照。此前公网视频 CI 受 HTTP 412/429/登录限制；不要绕过，不允许用 DOM fixture 替代成功证据。
- **AI-01 付费 AI**：只有用户主动开启并知悉额度后，以单条公开非敏感句子验证指定 Gemini/DeepSeek/自定义 AI；无配置时必须立即报告未就绪。不得为自动验收批量消费 Token。
- **NOT-DONE**：高质量语义补绘、会议自动字幕、AI 智能分句、完整英文 UI 尚未达到产品功能/实站验收标准，不能作为已通过项。

## 3. 验收回传格式

记录 `版本/浏览器/功能编号/操作步骤/期望/实际/错误码/是否可稳定复现/不含隐私的截图`。
故障优先级：P0（数据损坏、未经授权收费、密钥暴露）＞P1（常规功能不能工作、恢复失败）＞P2（平台兼容、翻译质量、可访问性）＞P3（视觉微调）。
不要求导出浏览器配置中的原始凭据。先复现并修复 P0/P1，再考虑合并或发布。

**验收出口：** 以上真实试用证据与发布风险逐条复核后再决定是否解除 Draft。当前保持 Draft，不合并 `main`。
