# v0.4.1 嵌入式字幕会话与精确录像身份绑定

日期：2026-10-16。仅实现后端路由与字幕会话安全补强；不涉及控制面板重新设计、项目命名或阶段性安装包交付。

## 修复的具体漏洞

在 v0.4.0 中，虽然最初按完整嵌入播放器 URL 选择子帧，但后续授权检查只核对 frameId 和 origin。对于同一 Panopto 站点内的另一段录制，单页应用（SPA）导航可能复用原有的 frameId 和 origin，使旧会话继续翻译新录制的可见字幕。

## 本轮改动与防护

1. 帧选择器返回临时 `identity`：经过校验的 HTTPS 完整播放器地址（含 query，不含 hash）。该值仅在插件进程内使用，**不写入 storage、日志、用户界面、诊断输出或云端**。
2. 权限批准后、脚本注入后，除了 frameId 和 origin，还验证 `identity` 完全一致。
3. 向目标子帧启动字幕时，传递 `expectedUrl`。子帧开始前验证本地 `location.href` 的完整规范化 URL；不一致则拒绝启动，避免脚本注入与消息交付之间的竞态。
4. 字幕轮询与翻译应答回来后都检查绑定的录像 URL。若同一子帧的 SPA 导航更换录像，停止旧字幕会话、移除覆盖字幕，不再读取新录制的字幕。
5. 对没有跨域嵌入选择的普通顶层 HTML5 视频，保留原有行为。仍需由用户手动开启 AI；绝不会静默转成 AI 提供商。

## 可复现自动化验收

- `tests/frame-route.test.js`：同 frameId + 同 origin 的不同录制 URL 产生不同 identity。
- `tests/embedded_frame_mv3_e2e.py`：真正的 Chromium MV3 子帧注入；错误录像身份拒绝启动；正确录像可见字幕启动；SPA 切换录制后旧字幕覆盖层自动移除。
- 其他网页版、字幕、ASR、OCR/PDF 回归沿用现有 CI。模拟跨域播放器由测试路由伪造，**并非真实 Panopto 登录账号或商业视频服务实测**。
